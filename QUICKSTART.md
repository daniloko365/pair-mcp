# Pair — быстрый старт

Pair — локальное приложение для macOS и MCP-инструменты в вашем обычном чате
Codex. Это не сайт и не отдельный чат-бот. Бесплатное приложение не оплачивает
вызовы внешних API за вас.

1. Скачайте [технический prerelease Pair 1.0.0](https://github.com/daniloko365/pair-mcp/releases/tag/v1.0.0),
   распакуйте ZIP, переместите Pair.app в «Программы» (или `~/Applications`)
   и откройте. Нужен официальный Codex,
   в котором вы уже вошли в аккаунт. В бете физически проверен Apple Silicon
   Mac; старые macOS, Intel, Windows и Linux не приняты тестами.
2. В Pair откройте **Подключения → Подключить к Codex**. API-ключ для первой
   проверки не нужен. Если хотите передавать задачи агенту, в **Паре** выберите
   папку проекта, в которой разрешена работа. Если нужен совет из платных API,
   отдельно добавьте свой ключ и выберите источник/модель в **Совете**.
3. Откройте **новый** чат Codex и отправьте одну строку:

   > `$pair-work Проверь, что Pair подключён. Не запускай платные модели.`

Если видите статус Pair — подключение работает. Теперь можно писать задачи в
том же обычном чате; отдельный чат Pair не нужен. Настройки открываются из
приложения или просьбой «Открой настройки Pair» в подключённом чате. При первом
делегировании Codex может попросить разрешить вызов Pair MCP; подтвердите его
для этой задачи. Режим, запрещающий все разрешения, остановит делегирование до
вызова модели.

> `$pair-work Используй мой сохранённый совет для проверки этой идеи. Покажи
> мнения участников, фактически использованные источники и свой итог.`

Для совместной работы сначала разрешите папку проекта в **Паре**. Следующий
пример работает с одной подпиской Codex; замените пример задачи своей целью:

> `$pair-work В разрешённом проекте попроси Codex по подписке написать небольшой
> парсер привычек и тесты. Дождись завершения задания, проверь изменённые файлы
> и запусти тесты. Затем дай второй сессии Codex короткую выжимку и попроси
> прочитать настоящий diff в режиме чтения. Назови это самопроверкой, а не
> независимым мнением второй модели; итоговый diff и тесты проверь сам.
> Не запускай двух писателей одновременно.`

Для независимого ревью можно **явно** выбрать Claude через OpenRouter API
(`mode=api, providerId=openrouter, permission=read-only`), если ключ настроен
и вы согласны оплатить вызов. Такой сценарий проверен на локальной бете.
Перед платным использованием задайте лимит на ключ у провайдера: официальный
Claude CLI не даёт Pair проверяемого жёсткого долларового предела счёта.
Claude по подписке и работа двух подписок пока не проверены; Pair не
переключает подписку на API незаметно.
Для Claude-рецензента нужен официальный Claude Code 2.1.248 или новее:
`read-only` ограничивает чтение файлами разрешённого проекта, а тесты и diff
перепроверяет исходный чат. Сам Claude CLI может сохранять служебные файлы
вне проекта — это не изоляция всего компьютера.

`$pair-work` — явный вызов навыка. Прямые команды MCP вводить не требуется:
навык сам использует инструменты `pair_status`, `pair_council`, `pair_job`,
`pair_delegate` и `pair_open_settings` по задаче. После обновления Pair начните
новый чат: старый может держать предыдущий MCP-процесс.

Если навык не виден, проверьте в Pair **Подключения → Подключить к Codex**,
затем создайте новый чат. В локальном Codex список MCP-серверов можно также
посмотреть через `/mcp`. Код на GitHub сам по себе не запускает локальный MCP:
Pair.app должен быть установлен на том Mac, где работает Codex.

Текущая Mac-бета подписана ad-hoc и **не нотариализована Apple**. Архив проверен
локально после извлечения, но установка на другом Mac не проверена. Если macOS
блокирует открытие, используйте обычное разрешение конкретного приложения в
Privacy & Security; не отключайте защиту macOS для всей системы ради беты.
Причину возможного предупреждения объясняет [Apple](https://support.apple.com/en-gb/102445).
Для исходников и подробных ограничений см. [README](README.md).
